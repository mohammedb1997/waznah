# وزنة — حاسبة وزنيات الشاهي الخليجي

موقع تفاعلي بصفحة واحدة (بدون خادم/Backend)، مبني بـ HTML/CSS/JS خالص — يفتح مباشرة من أي متصفح أو يُنشر على أي استضافة ثابتة.

## الملفات

| الملف | الوصف |
|---|---|
| `index.html` | هيكل الصفحة (الهيرو، التبويبات، الحاسبات الثلاث، دليل الدرجات، النصائح) |
| `style.css` | نظام التصميم الكامل (الألوان، الخطوط، الاستجابة للجوال، الطباعة) |
| `app.js` | كل منطق الحساب والتفاعل — بحث، مفضلة، مشاركة، تلميحات التطابق، الصور الرمزية، الأنظمة الديناميكية |
| `pb-loader.js` | يقرأ البيانات من PocketBase مباشرة، مع رجوع تلقائي للنسخة الثابتة لو تعذّر الاتصال |
| `site_data.js` | نسخة احتياطية ثابتة من البيانات (257 صنفاً + 18 درجة تصنيف) |
| `admin.html` / `admin.js` / `admin.css` | لوحة تحكم كاملة لإدارة الأصناف والصور وإنشاء أنظمة جديدة |
| `دليل_أسماء_الصور.md` | جدول يربط كل صنف بمعرّفه — لتسمية ملفات الصور الحقيقية بشكل صحيح |
| `images/` | مجلد اختياري تضيفه بنفسك لصور الأصناف الحقيقية (فارغ حالياً) |

**الأربعة ملفات لازم تبقى بنفس المجلد** — الصفحة تحمّلها بروابط نسبية.

## التشغيل المحلي

افتح `index.html` مباشرة بأي متصفح. ما يحتاج سيرفر أو تثبيت أي شي.

## النشر على الإنترنت (اختر واحدة، كلها مجانية)

### Netlify (الأسهل)
1. روح [netlify.com](https://netlify.com) وسجّل دخول.
2. اسحب مجلد `wazna-site` كامل وأفلته في صفحة "Sites".
3. خلاص — بيعطيك رابطاً فورياً، وتقدر تربط دومين خاص لاحقاً من الإعدادات.

### GitHub Pages
1. أنشئ مستودع (Repository) جديد على GitHub وارفع الملفات الأربعة.
2. من إعدادات المستودع (Settings → Pages)، فعّل النشر من الفرع الرئيسي (`main`).
3. الموقع بيصير متاحاً على `username.github.io/repo-name`.

### Vercel
1. روح [vercel.com](https://vercel.com) وسجّل دخول.
2. New Project → ارفع المجلد أو اربطه بمستودع GitHub.
3. Deploy — بدون أي إعدادات إضافية (الموقع ثابت بالكامل).

## لوحة التحكم (إدارة كاملة بدون كود)

افتح `admin.html` (رابط "لوحة التحكم" بأسفل الصفحة الرئيسية). سجّل دخول بنفس حساب الأدمن (superuser) اللي تدخل فيه على `/_/`، وبعدها تقدر:

- **تضيف/تعدّل/تحذف** أي صنف بأي من الأنظمة الثلاثة الحالية، مع رفع صورة له مباشرة من نفس النموذج.
- **تدير درجات الأوراق** (OP, BOP...) بنفس الطريقة.
- **تنشئ نظام إبريق/مصدر جديد بالكامل** بضغطة زر — تختار اسم النظام والشكل الحسابي (مدى ثلاثي حسب السكر / قيمة واحدة لكل لتر / مدى ثلاثي مع نطاق سكر منفصل)، ولوحة التحكم تنشئ الكولكشن المناسب في PocketBase تلقائياً ويظهر النظام كتبويب كامل بالموقع الرئيسي فوراً — بدون ما تلمس أي سطر كود.

⚠️ **تنويه أمان (محدّث):** لوحة الإدارة لا تحفظ توكن Superuser في `sessionStorage` أو `localStorage`؛ التوكن يبقى في ذاكرة الصفحة فقط ويختفي عند إعادة تحميلها. ما زال المسار الأفضل للإنتاج هو عزل صلاحيات Superuser خلف BFF/Cloudflare Worker وعدم كشف API الإدارة مباشرة للمتصفح.

## نقل البيانات إلى PocketBase (اختياري)

الموقع أصبح **ديناميكياً** — يقرأ البيانات مباشرة من PocketBase عند كل زيارة، ولو تعذّر الاتصال (النفق واقف، السيرفر مقفول...) يرجع تلقائياً لنسخة `site_data.js` الثابتة المرفقة، فالموقع ما يتوقف أبداً. شريط صغير أعلى الصفحة يوضّح أي مصدر يعرض الآن (🟢 حي من PocketBase / 🟡 نسخة محفوظة محلياً).

### خطوة واحدة فقط لنقل البيانات

من مجلد `pocketbase/` المرفق:

```bash
pip install requests
python3 migrate_to_pocketbase.py
```

يطلب منك إيميل وكلمة مرور حساب الأدمن (superuser) بتطبيق PocketBase وقت التشغيل — ما تُكتب أبداً بالسكربت أو تُرسل لأي جهة ثانية. بعدها ينشئ 4 كولكشنز (`moka_teas`, `teapotA_teas`, `teapotB_teas`, `tea_grades`) بما فيها حقل صورة (`photo`) جاهز، ويستورد كل الـ275 سجلاً دفعة وحدة. جرّبته محلياً بمحاكاة كاملة قبل ما أسلّمك إياه، ونجح 100% — لكن ما قدرت أشغّله ضد سيرفرك الفعلي لأن بيئتي هنا بدون اتصال إنترنت خارجي، فتابع مخرجاته أول مرة تشغّله وأخبرني بأي خطأ لو صار.

### تحديث رابط PocketBase

الرابط الحالي مكتوب في أول سطرين من `pb-loader.js` (`POCKETBASE_BASE_URL`) — ونفس الرابط لازم يُكتب في شاشة الدخول بلوحة التحكم (`admin.html`) كل مرة تسجّل دخول. لو تغيّر رابط ngrok (شي متوقع، الروابط المجانية مؤقتة) أو انتقلت لدومين ثابت لاحقاً، حدّث هذا السطر فقط.

### ⚠️ CORS وngrok — إعداد الإنتاج

جرّبت الموقع فعلياً ضد رابطك المرفق ولقيت أن أول محاولة اتصال ترجع **خطأ CORS** من سيرفرك (رفض الطلب قبل ما يوصل للبيانات أصلاً) — الموقع يتعامل معه بسلاسة (يرجع تلقائياً للنسخة المحفوظة)، لكن يعني الوضع الحالي إن القراءة الحية **ما تشتغل بعد** لين يُحل. سببه غالباً أحد اثنين:
1. إصدار PocketBase عندك مربوط بإعداد CORS مقيّد بدل الافتراضي المفتوح.
2. نفق ngrok المجاني نفسه يتدخل بطلب الـ OPTIONS (preflight) قبل ما يوصل لـPocketBase.

**الحل الموصى به:** لا توسّع CORS إلى `*` في بيئة الإنتاج. قيّد Origins إلى نطاق موقعك، مثل `https://mohammedb1997.github.io`، واسمح برأس `Authorization` للوحة الإدارة فقط. PocketBase يدعم تحديد Origins عبر إعداد `--origins`، والافتراضي في الوثائق الحالية هو `*`. راجع ملف `pocketbase/CORS-PRODUCTION.md` المرفق. citeturn945563search1turn945563search0

أما `ngrok-skip-browser-warning` فتمت إزالته من الطلبات العامة في `pb-loader.js` لأنه رأس مخصص يفرض preflight؛ إذا احتجت تجاوزه في ngrok فالحل الإنتاجي الأنظف هو Proxy/BFF، وليس إضافة الرأس لكل طلب من المتصفح. ngrok يذكر استخدام هذا الرأس لتجاوز صفحة التحذير. citeturn945563search7

### رفع صور الأصناف

لو عندك صور جاهزة محلياً بمجلد `images/` (بنفس تسمية `دليل_أسماء_الصور.md`) وقت ما تشغّل سكربت النقل، يرفعها هو تلقائياً مع كل سجل. أو ترفعها لاحقاً يدوياً من لوحة تحكم PocketBase مباشرة (`/_/`) لأي صنف تختاره.

## إضافة صور حقيقية للأصناف (النسخة الثابتة فقط)

الموقع جاهز يستقبل صور حقيقية بدون أي تعديل بالكود:

1. أنشئ مجلد اسمه `images` بجانب باقي ملفات الموقع (نفس مستوى `index.html`).
2. احفظ كل صورة بصيغة `.jpg` وسمّها بمعرّف الصنف بالضبط — الأسماء والمعرّفات كاملة موجودة بملف `دليل_أسماء_الصور.md` المرفق (257 صنفاً).
3. مثال: صورة "شاي 999" (إبريق الموكا) تُحفظ باسم `images/T001.jpg`.
4. حدّث الصفحة — الصورة تظهر تلقائياً بدل الأيقونة الملوّنة، بدون أي تعديل على `app.js` أو `index.html`.

أي صنف بدون صورة يبقى يعرض أيقونته الملوّنة (لون + حرفين من الاسم) تلقائياً — لا يوجد رابط مكسور أو صندوق فارغ.

## تحديث البيانات لاحقاً

كل بيانات الشاهي موجودة بصيغة JSON داخل `site_data.js` (متغيّر `TEA_DATA`) بثلاث مصفوفات: `moka` (إبريق صانع الشاهي)، `teapotA` و`teapotB` (الإبريق العادي، مصدرين)، بالإضافة لمصفوفة `grades` (درجات الأوراق) وكائن `matches` (تلميحات التطابق بين الأنظمة).

لإضافة صنف جديد أو تعديل رقم: عدّل ملف الإكسل الأصلي (`قاعدة بيانات وزنيات الشاهي - السعودية.xlsx`) أولاً — هو مصدر الحقيقة — ثم اطلب من Claude إعادة توليد `site_data.js` منه، عشان الملفين يبقون متطابقين دائماً.

## ما الذي لا يوجد بعد (نسخة MVP)

- بدون حسابات مستخدمين أو قروبات (مخطط لها لاحقاً في `دليل_تأسيس_الموقع` بالإكسل).
- المفضلة محفوظة محلياً بالمتصفح فقط (localStorage) — لا تُزامَن بين الأجهزة.
- لا يوجد بحث صوتي أو تطبيق جوال منفصل — الموقع متجاوب (Responsive) ويعمل جيداً على الجوال كبديل.
